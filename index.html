DIAGNOSTIC DETAIL // DS-001

Card overflows on mobile

88% CONFIDENCE
Visual QA Medium Severity Needs Review
Observed Symptom:

In the mobile viewport (390px), the .feature-card element extends past the display border. Its right card boundary is clipped by 130px.

LIKELY ROOT CAUSE

A hardcoded rule width: 520px in styles.css forces fixed dimensions larger than the 390px viewport container.

REPRODUCE IN DEMO

Toggle to Chapter 01 (Mobile tab) and inspect the card’s right edge extending beyond the simulated screen.

✳ SOCRATIC MENTOR QUESTION HINT FIRST

Which CSS width rule stays identical when the viewport gets narrower, and which rule responds fluidly?

RECOMMENDED SOLUTION

Make the element fluid with width: 100%, then establish its desktop ceiling with max-width: 520px.

CONTEXTUAL VIEWPOINTS // ONE AUDIT PASS
Security

No injection or remote risks found; pure styling scope.

Code Quality

Eliminating static widths ensures responsive maintainability.

Visual QA

Card now flexes within 390px mobile viewport margins.

DIAGNOSTIC DETAIL // DS-002

Menu control needs an accessible label

95% CONFIDENCE
Accessibility Low Severity Needs Review
Observed Symptom:

The sample navigation menu button has no accessible name in the synthetic DOM tree, failing WCAG 4.1.2.

LIKELY ROOT CAUSE

An icon-only button without text content or an aria-label attribute.

REPRODUCE IN DEMO

Inspect node <button> in the Console & DOM tab under Chapter 01.

✳ SOCRATIC MENTOR QUESTION HINT FIRST

If a screen reader user navigates to this icon control, what words would their assistive tech speak aloud?

RECOMMENDED FIX

Add aria-label="Open navigation menu" to the button element.
